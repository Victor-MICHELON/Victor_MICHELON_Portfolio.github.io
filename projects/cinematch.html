CineMatch, a recommender that also works on films nobody has rated

A movie recommender that blends eight signals, from what the plot is about to how the audience rated it, with weights that adapt to each film. When a film has no ratings, the engine leans on its content instead of going blind, and every suggestion says why it is there. An offline evaluation on MovieLens measures what that is worth.

  • ×5.6hits on films with no ratings, against collaborative filtering alone (19.1% vs 3.4%, tuned weights)
  • 12.2 MBof artifacts instead of 618 MB, for exactly the same similarities
  • 1.4 msper query (median) on a laptop
  • 6,195films, 43% of them with no audience ratings
Try the live demo Code on GitHub

What sets it apart

It also recommends the films nobody has rated yet

The stakes. On a platform, a film with no ratings is never recommended, so never watched, so never rated. This is the cold-start problem: new releases and niche films stay invisible. In CineMatch’s catalogue, it concerns 43% of the films.

The usual approach

Collaborative filtering: “people who liked this film also liked…”. Very effective when a film has many ratings.

Where it breaks. It has nothing to say about a film with no ratings. The fallback, “same genre, same actor”, finds films that look alike on paper, not on screen.

What I did differently

  • A hybrid engine with 8 signals: what the plot means (SBERT embeddings), topics, mood, genre, cast and crew, origin, era and audience ratings.
  • Weights that adapt to each film. When a film has no ratings, the audience weight is not lost: it moves to plot, topics and mood.
  • Every suggestion explains itself (“same director · similar mood”), and a radar shows the weights used.

The proof

×5.6

On 2,330 test queries where the source film’s ratings are hidden, collaborative filtering alone puts a film the user really liked next in its top 10 in 3.4% of cases. The hybrid with tuned weights: 19.1%. With the handcrafted rules the app uses by default: 9.1% (×2.7). Example: Parasite has no MovieLens rating, and CineMatch suggests The Host and Snowpiercer: same director, same tone.

What it does not do. A plain list of the most-rated films still scores higher on this test (35.4%), with or without ratings. But it recommends the same few films to everyone, 1.4% of the catalogue, whatever the starting film; the hybrid’s suggestions reach about half of it.

What it shows. Designing a system for its hard case, then measuring it honestly instead of asserting it.

The problem

Keyword filtering (“same genre, same actor”) misses what makes two films feel alike, while pure collaborative filtering fails on films nobody has rated. CineMatch combines both families of signals and stays explainable: each card names the two signals that drove it, and a radar shows the exact weights behind the ranking.

The hard case first. Parasite (2019) has no rating in MovieLens. CineMatch returns The Host, Snowpiercer, The Gangster, the Cop, the Devil and The Roundup: the first two share its director, Bong Joon-ho, and all four share its origin and its tone. Two rules fire (non-English, very popular) and, since there are no ratings, the audience weight moves to the content signals.

The easy case, for comparison: Pulp Fiction (1994) has plenty of ratings and returns Reservoir Dogs, Se7en, The Usual Suspects and Kill Bill: Vol. 2.

The data

  • Metadata, posters and trailers from the TMDB API, fetched by the pipeline.
  • Ratings from MovieLens ml-latest-small (610 users), for the audience signal and for the evaluation.
  • Catalogue: 6,195 films from 1916 to 2024. Some titles are shared by several films, such as two Aladdin, so the engine works on row positions, never on titles.
Cold start

43% of the catalogue has no MovieLens rating: recent films, non-English films, niche titles. For them, the audience signal is empty, and its weight is moved to the content signals instead of being silently wasted.

Approach

The eight signals

No n × n matrix is stored. Each signal is kept in factorised form: the similarity row of film i is F @ F[i] on L2-normalised rows, which is exactly the cosine, computed on demand.

Scoring

For a source film i and a candidate j, the score is a normalised weighted sum of the eight similarities:

S(i,j)=∑k=18wk(i)Mk[i,j]∑k=18wk(i)

Each term wk · Mk[i, j] is a contribution: the two largest give the reason printed on the card. With several source films (“I liked A, B and C”), their scores are averaged. The “% MATCH” on each card is this normalised score, a relative ranking indicator, not a probability.

Adaptive weights

The weights start from a base profile and are adjusted by four readable rules, stored as data in a WeightConfig, so the same rules can be switched off one by one (ablation), tuned by Optuna and applied by the app. Pick a profile to see how the blend changes; these are the values the engine computes.

Evaluation

The question a recommender has to answer: which films will this user like next? The protocol is built so that the answer cannot leak.

  • Temporal split per user: each user’s oldest 80% of ratings for training, the newest 20% for testing. A liked film is rated 4 or more.
  • Queries: one of the user’s five most recent liked films in training; the relevant answers are the films the user liked in the test period. Already-rated films are excluded.
  • No leakage: the audience signal is rebuilt on the training part only.
  • Test set used once: 20% of users tune the weights; the other 472 users (2,330 queries) give the final numbers, with 95% intervals from a 1,000-draw bootstrap.
  • Cold start: every query is replayed with the source film’s ratings hidden, as for the 43% of the catalogue that has none.

Reading it honestly

  • On films that already have ratings, popularity wins. The most-rated list comes first and collaborative filtering alone comes close; the hybrid does not beat them there.
  • Cold start is where the hybrid earns its keep. Without ratings, collaborative filtering collapses (0.034), while the tuned hybrid keeps 0.191 (×5.6) and a ten times higher NDCG@10.
  • The rules help: NDCG@10 goes from 0.044 to 0.057 (+29%), mostly through the “very popular” rule (−1.27 points when it is removed).
  • Tuning helps more (+22% on standard queries, ×2.1 in cold start), but it shifts weight to era and audience, so it partly re-learns popularity. The app keeps the handcrafted rules by default, which stay closer to “films like this one”, and offers the tuned profile in advanced mode.

Implementation

From 618 MB to 12.2 MB

The first version shipped eight dense 6,203 × 6,203 similarity matrices: 618 MB through Git LFS and about 700 MB of RAM, so the hosted demo was slow to start. Storing the factors instead (embeddings, sparse bag-of-words and rating matrices) gives exactly the same cosines, computed per query.

  • 618 MBon disk, first version (dense matrices)
  • 12.2 MBon disk now (factors, no pickle)
  • 708 → 180 MBof process RAM
  • 1.4 msper query, median (2.2 ms at p95)

The price is a query that costs 1.4 ms instead of a fraction of a millisecond, which no user can notice. The audience signal is rebuilt identically (correlation 1.000 with the old one); the mood signal, whose original code was lost, is rebuilt from scratch (non-regression report).

  • Engine separate from the UI

    cinematch/ has no Streamlit import: it is type-checked with mypy --strict, covered at 99% by tests, and reused as is by the evaluation code.

  • Rules as data

    The magic numbers live in a WeightConfig dataclass, so the rules the app applies are exactly the ones that were ablated and tuned.

  • No pickle

    Artifacts are Parquet, .npy (allow_pickle=False) and .npz, checked against a SHA-256 manifest when they load.

  • One command rebuilds everything

    python -m pipeline.build goes from the TMDB API and MovieLens to the eight signals.

One similarity row, from cinematch/data.py:

def similarity(self, signal: str, idx: int) -> FloatArray:
    if signal in EMBEDDING_SIGNALS:            # plot, mood
        emb = self.embeddings[signal]
        return emb @ emb[idx]
    if signal in SPARSE_SIGNALS:               # topics, genre, cast, origin, audience
        fac = self.factors[signal]
        row = fac[idx].toarray().ravel()
        return np.asarray(fac @ row, dtype=np.float32)
    if signal == "context":                    # era & fame
        pop = np.exp(-np.abs(self._pop - self._pop[idx]) / self.context.pop_sigma)
        year = np.exp(-np.abs(self._year - self._year[idx]) / self.context.year_sigma)
        return ((pop + year) / 2).astype(np.float32)

The app

Beyond one film: “I liked A, B and C” queries, filters (decade, genre, language, runtime), a diversity slider, manual weight sliders, 4, 8 or 12 results, TMDB links and trailers, and an English/French interface.

Limits and roadmap

Limits

Popularity is a strong baseline. On films that already have ratings, the hybrid does not beat the most-rated list. A learned blender (LightGBM LambdaRank over the eight similarities) is the natural next step.

  • Small data: 6,195 films and ml-latest-small (610 users). Next: MovieLens 25M and a FAISS index over the embeddings.
  • TMDB metadata drifts: the pipeline queries the live API, so a rebuild can change keywords or popularity slightly.
  • Two defaults, two numbers: the ×5.6 comes from the tuned profile; the handcrafted rules the app uses by default give ×2.7.

Already done, from the first version’s list: offline evaluation, all four rules active, a complete pipeline, weight tuning, diversity re-ranking (MMR) and an English/French toggle.

Reproduce

git clone https://github.com/Victor-MICHELON/CineMatch-recommender.git
cd CineMatch-recommender
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -e ".[dev]"
export TMDB_API_KEY=your_key      # optional, for posters and trailers

streamlit run app.py              # downloads the 11 MB artifacts archive on first launch

# rebuild everything from TMDB + MovieLens
pip install -e ".[pipeline]" && python -m pipeline.build --zip
# offline evaluation -> reports/eval.md
pip install -e ".[eval]" && python -m evaluation.run

Tests: pytest (pytest -m "not slow" without local artifacts). A Dev Container is included for GitHub Codespaces.

Data: TMDB (this product uses the TMDB API but is not endorsed or certified by TMDB), MovieLens (Harper & Konstan, 2015), Sentence-Transformers (Reimers & Gurevych, 2019).

Python, sentence-transformers, NumPy, SciPy, pandas, Optuna, Plotly, Streamlit, pytest, mypy
