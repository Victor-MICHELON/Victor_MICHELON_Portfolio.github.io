Deep learning on MRI · December 2025

Brain tumor MRI classification with Grad-CAM

An end-to-end deep learning workflow that classifies brain MRI scans into four categories. A CNN trained from scratch is the baseline for a fine-tuned EfficientNetB0, and Grad-CAM shows which regions drive each prediction, because in medical imaging accuracy alone is not enough.

  • 97.8%test accuracy, EfficientNetB0 fine-tuned
  • 92.1%test accuracy, CNN baseline
  • 0.79 → 0.94recall on meningioma, the hardest class
  • 1,311held-out test scans

The problem

Brain tumors present differently across MRI scans, and early detection improves patient outcomes. The goal is a system that recognizes four diagnostic categories, glioma, meningioma, pituitary tumor and no tumor, and that makes its decisions inspectable: Grad-CAM heat maps highlight the regions that most influence each prediction.

Disclaimer

Educational and research project. It is not a medical device and must not be used for diagnosis.

The data

The Brain Tumor Dataset on Kaggle: labeled axial MRI slices with variations in acquisition quality, brightness, orientation and anatomy.

  • Training: 5,712 scans, split 80/20 with stratification into 4,569 for training and 1,143 for validation.
  • Test: 1,311 scans: 300 glioma, 306 meningioma, 405 no tumor, 300 pituitary.

Approach

  • Baseline: custom CNN

    Stacked Conv2D and MaxPooling2D layers, Dropout regularization, a Flatten and dense head, trained from scratch with Adam. It sets the bar to beat.

  • Transfer learning: EfficientNetB0

    Pretrained on ImageNet, frozen then partially fine-tuned, with a new head: GlobalAveragePooling2D, dense ReLU layer, dropout and softmax. Better generalization and faster convergence.

Explainability with Grad-CAM

Grad-CAM heat maps highlight the regions that most influence each prediction, here on one random test sample per class (seeded).

How to read it

On these samples the activation concentrates on the lesion area, which is consistent with the model using tumor-related features. This is qualitative evidence only: it is not a quantitative validation, such as overlap with the dataset’s segmentation masks, and it does not rule out dataset biases.

Reproducible pipeline

The notebook is the original exploratory work and the source of the results above. The src/ package addresses its main weaknesses:

ModulePurpose
dedup.pyPerceptual-hash (dHash) clustering of near-duplicates: a leak-free train/validation split, grouped and stratified, and detection of training images that also appear in the test set
data.pytf.data pipeline with Keras augmentation layers, replacing the deprecated ImageDataGenerator
models.pyCNN baseline and EfficientNetB0; fine-tuning keeps BatchNorm frozen
train.pyTrains either model with the same split, augmentation, class weights and epoch budget, and writes a leakage report
gradcam.pyGrad-CAM for both architectures, also on reloaded models
localization.pyQuantitative Grad-CAM validation against tumor masks: pointing game, IoU@0.5, energy in the mask, against a random heat-map baseline
evaluate.pyTest metrics with bootstrap 95% intervals, calibration (ECE), top confusions, Grad-CAM gallery of the most confident errors
 
python -m src.train --model cnn      # -> artifacts/cnn.keras
python -m src.train --model tl       # -> artifacts/tl.keras
python -m src.evaluate --model artifacts/tl.keras --seg-dir /path/to/DATASET/segmentation
pytest                               # synthetic-data tests, no dataset needed
Status

The code is tested on synthetic data, with unit tests and a train-then-evaluate smoke run that includes Grad-CAM on reloaded models. It has not yet been run on the real dataset, so the numbers on this page still come from the notebook. Segmentation images do not share file names with the classification ones, so they are matched by content (dHash) to know whether each belongs to the test set, the training set or neither; only the test group gives an unbiased localization score.

Limits and next steps

Possible leakage

Validation accuracy (99.9%) is noticeably higher than test accuracy (97.8%), a sign of near-duplicates shared between training and validation. src/dedup.py quantifies and removes them; re-running with it is the next step and may lower the reported figures.

  1. Classification, not segmentation: the model predicts a category but does not localize tumors pixel by pixel.
  2. Single run: one seed; with 1,311 test images the 95% interval on accuracy is roughly ±0.8 point.
  3. Generalization to real-world MRI: domain shift across scanners and protocols is untested; there is no external validation set.
  4. Explainability: the Grad-CAM figures are qualitative; src/localization.py provides the quantitative check, still to be run on the real data.

Reproduce

git clone https://github.com/Victor-MICHELON/Brain_Tumor_Classification.git
cd Brain_Tumor_Classification
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# dataset: Kaggle indk214/brain-tumor-dataset-segmentation-and-classification
export DATASET_DIR=/path/to/DATASET/classification   # contains Training/ and Testing/
jupyter notebook mri-tumor-classification-cnn-transfer-learning.ipynb

A GPU is strongly recommended for fine-tuning. Seeds are fixed (SEED = 42), but GPU runs are not bit-for-bit deterministic.

Python, NumPy, pandas, TensorFlow and Keras (EfficientNetB0), scikit-learn, Matplotlib, Seaborn, Plotly, Grad-CAM implemented by hand
